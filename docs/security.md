# Security model

Every application table has RLS and explicit SELECT, INSERT, UPDATE and DELETE policies restricted to the `authenticated` role and scoped to `(select auth.uid())`. Composite foreign keys prevent cross-user references even when identifiers are guessed. Google is the only UI authentication method and requests identity-only scopes. Sessions use Supabase SSR cookies; server layouts verify users. Redirects accept only same-origin relative paths. Text length and structural constraints exist in both Zod and PostgreSQL. User HTML is never rendered. Account deletion requires an authenticated session, a same-origin request, an explicit confirmation header and a per-user rate limit.

Authenticated workspace pages — including Today, Week, Month, Search, Summary, Tasks, Focus and the remaining app routes — are marked `private, no-store`. The service worker caches only the public shell and immutable static assets, never private workspace navigations. Cached workspace snapshots remain local to the browser for offline use and are removed together with pending operations when the user signs out or deletes the account. The account-deletion response also requests browser storage and cache removal through `Clear-Site-Data`.

Internal telemetry accepts only small same-origin JSON requests, records sanitized technical metadata and never records user content. Rate-limit storage is bounded to prevent unbounded process memory growth. Account deletion denies the request if the distributed limiter is unavailable. Telemetry may fall back to a per-instance memory bucket so local development still works. Browser defenses include a nonce-based CSP (set in the request proxy), frame denial, MIME sniffing protection, cross-origin resource policies and a restrictive permissions policy.

The publishable key is intentionally browser-safe; the service-role key must exist only in server environment variables and is used for verified account deletion and the distributed rate-limit RPC. Operators must disable unused Supabase providers, keep dependencies patched, configure exact OAuth redirects, review CSP changes and rotate credentials if exposed. RLS must never be disabled in production.

Completing or undoing a task records the last action in `task_occurrence_state`. Offline replay consults that row so a newer uncomplete on another device is not overwritten by an older queued complete. System notifications while a fully suspended PWA is in the background remain an OS/browser limit.

Focus tables (`focus_presets`, `focus_sessions`, `focus_intervals`, `focus_goals`) follow the same RLS and ownership-FK model. A partial unique index enforces one active session per user. Session notes and parked distractions are private account data: they appear in full JSON backups, are omitted from analysis CSV by default, and must never be sent to product analytics or system notification bodies. Live sessions are terminalized on restore so timers and notification schedules are not resurrected without user action.
